## 修正内容及负向证据

### 腿部评分不再丢掉安全释放路径

资产无关的 18 帧合成动作复现了明确缺陷：第 11 帧安全释放候选评分 `0.0380362`，清零评分 `0.0368124`。旧实现只比较评分，选择清零，使两足附加修正变化 `0.0320899`，超过 `0.0160449` 单步上限；IK 全程开启，并非开关要求撤销修正。

现在清零会违反步长限制时，先以已通过原碰撞、IK、高度、位移和未来释放检查的候选为后备结果，再比较其他候选。该例第 11 帧释放到约 `0.0160449`、第 12 帧回到零。旧实现两项失败，新实现及 IK 开关变体全部通过，最大修正仍 `0.0514693`，没有通过关闭求解掩盖问题。原有 1719 帧整片及 97 帧窗口输出与 FE046 版本逐字节一致。见 [腿部收据](leg-release-metrics.json)。

安全不等同于每个平方残差都变小：已经低于容差的某个碰撞对，释放时可以具有稍大的平方残差，但不得突破任何原空间保护，最大穿插也不得增加。

### 脚部 floor 回退细化

完整步、半步、四分之一步的离散选择会在稳定 IK 分支中形成台阶。首次找到安全步后，现在在拒绝／接受区间内做最多 12 次细化；候选保留逐碰撞对和 IK 误差保护，并要求实际踝部至 floor 目标的残差不高于已接受候选。

慢抬脚测试的稳定分支第 55–63 帧，最大目标跳步 `0.0402708 → 0.00328848` PMX，原输入每帧 `0.002`。冻结 D91E 版稳定失败，新版通过；整个 101 帧仍检查空间和 IK 保护，不把早期分支跳变藏在连续性断言中。真实 1719 帧／3438 脚帧点仅 51 项改变，水平运动不变，IK 误差增量最大 `0.009999943 ≤ 0.01`，碰撞对超限为 0。不能宣称新版每帧 IK 残差都优于旧版：它仍使用原有误差容差。见 [贴地复核](floor-review.md)、[数据](floor-metrics.json)。

### 避让阶段也保护输入手掌朝向

此前接触阶段保持的是避让后的掌向，避让自身已旋转手掌。现在避让移动手臂后，对可写自由腕骨进行反向补偿，尽量保留该阶段输入掌向；新增补偿限制为 30°，手指局部旋转不用于消除误差。固定轴、付与和不可旋转腕骨不新增或重写该腕轨道。

补偿重新检查双方手腕、手肘及臂段采样，因为腕骨挂载的盒体／胶囊可能转入另一臂。不能安全完整补偿时，保留安全的部分结果。全片相对 stage4 的 stage5 最大掌向偏差，左手 `9.05853° → 1.60465°`、右手 `11.93921° → 0.72666°`；残留最大值在第 131 帧。指骨局部旋转增量仍为 0，避让最大关节变化不变，后续接触没有把掌向收益撤销。见 [全片掌向数据](palm-metrics.json)。

负向控制明确区分三个范围：

- 冻结 D91E 求解器在原有可达球障碍的掌向断言失败；当前实现通过，避让仍实际生效。
- 独立 helper 测试构造 Avoid 已完成姿态，左腕偏心盒体／胶囊的完整补偿会造成约 `0.2` PMX 对侧穿插。原守卫将深度限制到 `0.00197053 ≤ 0.002`，仍接受部分补偿；仅删除此守卫的版本稳定失败。此用例不冒充完整 `Run` 自动产生该姿态。
- 八个不可写腕骨／有无原关键帧场景中，Avoid 仍移动手腕约 `0.350442` PMX，腕轨道保持原 0 或 2 个关键帧及其插值。仅删除 controlled 的可写筛选条件会稳定失败。正式 Advanced 另通过完整 `Run` 检查相同标记与关键帧保护。

见 [掌向保护复核](palm-guard-review.md) 和相应正／负日志。30° 是腕部新增补偿预算，不是整条手臂 Avoid 的总旋转预算。

## 继续优化的边界

两处 floor 问题仍明确存在：近伸直 IK 分支在慢抬脚 47→48 帧仍可产生约 `0.171438` PMX 跳步；真实动作右脚 770→771 帧一帧跳过整个来源高度 confidence 区间，仍撤销约 `0.222694` PMX 竖直修正。前者涉及可接受 IK 分支，后者涉及时间上的接触释放；本轮步长细化没有声称解决它们。
