# 动作适配算法实测审计（2026-10-10）

发布版的回避有效，但它的检查范围、接触目标和阶段组合方式存在实质性缺口。不能把“计算成功”或“接触残差很小”解释成最终姿势没有穿入。本次没有将实验性的二次回避合入正式算法。

## 输入和证据范围

- 用户提供的 Sour `Black.pmx` → 阿芙 2.0，`Stay Tonight Heaven Lee Ver. 动作.vmd`，0–1718 帧。尚未确认 Sour 就是动作作者使用的原模型。
- 从 libMMD `e4aca1048af9216d65bea91ec734710e360bcdd0` 的干净归档编译七个 sizing 源文件，MSVC 19.51、SSE2；IO 复用已有 libMMD 静态库。资产和库 SHA256 见 `receipt.json`。
- 基础位移、姿态、扭转保持一致，单独组合回避、手腕、手指、地面接触；默认 40 次迭代、接触距离 0.3、回避余量 0.05、容差 0.01（PMX 单位）。本报告的 `all` 不包含多人接触或相机。
- C4D 2026.4 实际加载 v0.9.3.3 发布二进制，模型和 VMD 均按 8.5 导入，关闭物理。截图来自 native MCP `capture_viewport`，没有改画面。
- 在 313、776、854 帧读取三个版本模型的左右臂根、肘、腕：54 个位置与离线 FK × 8.5 的最大差异为 **0.0000049884 场景单位**。这支持这些代表帧的算法/宿主一致性，不等于所有骨骼、IK、物理和网格都已验证。

## 已定位的问题

1. **回避漏检手臂中段和表面。** `Solvers/MMDMotionConstraints.cpp::Avoid` 只把肘、腕当作点。313 帧肘/腕没有超差，段采样仍有 5 条，最大深度 0.50768；这是代理几何下的明确漏检。该帧前视图有遮挡，不能仅凭这一张图宣称网格穿入量。
2. **接触会破坏回避。** `ApplyConstraints` 依次执行 Avoid 和 Contact，Contact 不重新检查避障。776 帧肘/腕从 0 条变成 4 条，最大深度 0.23666，涉及对侧手/肘刚体。258 帧从仅回避的肘/腕 0、段采样 0，变成全开时 3 和 19，段采样最大深度 0.67474。
3. **接触目标不等于手掌贴合。** `Contact` 让接触组内效应器趋向同一个中心；腕骨重合没有保留手掌厚度、原始相对偏移或接触方向。776 帧双腕距离从仅回避的 0.58902 降到 0.0001017，但这不意味着手的表面关系正确。手指使用末节骨节点，连通组也共享中心；258 帧截图中手势明显被收拢，不能用中心残差小作为手势质量指标。
4. **报告反映求解时的阶段，不是最终复检。** 回避 + 手腕仍报告 5 条 unresolved、手腕接触 0 条 unresolved；对最终 Contact 输出重查却有 57 条肘/腕刚体超差。UI/MCP 应明确区分求解完成和最终约束质量。
5. **触发和动作连续性还不够。** 当前是单帧绝对腕/指骨距离，没有接触滞回或姿态保持项。原 Python 在接触距离上还使用模型长度比，并包含指端调整；其变量名 `org_palm_mean` 实际取自 `ArmAlignmentOption.ratio`，不能误称为直接除以手掌长度。当前 C++ 不是这部分高级行为的完整等价移植。

关键源码：`dependency/libMMD/src/MotionSizing/Solvers/MMDMotionConstraints.cpp`、`Pose/MMDMotionPose.cpp::SolveGoals`，以及 `C:/code/vmd_sizing/src/service/parts/ArmAlignmentService.pyx` 的 `prepare_wrist` 和距离判定。

## 二次回避反例

在隔离源码副本中只增加 Contact 后再运行一次 Avoid（见 `cleanup-experiment.diff`）。回避 + 手腕的最终肘/腕超差记录从 57 降至 1；但 13 个接触帧的双腕平均距离由 **0.000177 → 0.368607**，最大距离由 **0.000305 → 0.537159**。平均间距按 8.5 倍率约为 3.13 场景单位。

因此这个串行补丁会重新把双手推开，没有作为正式修复提交。实验也不证明当前“腕骨重合”就是正确接触要求；它证明两个现有目标正在互相抵消，需要先修正接触语义，再联合求解。

## 建议实施顺序和验收

1. 增加最终阶段复检：返回具体帧、骨骼、刚体、深度以及不满足的接触目标，在预览中显示。先让质量报告可信。
2. 用手掌/指端接触代理及来源相对偏移建立目标，保留厚度和方向；避免把一组手指全部压到同一位置。对指定接触对使用表面接触约束，而不是简单忽略整个对侧手臂碰撞。
3. 将整段手臂（带半径的胶囊或保守代理）避障与接触一起求解；同时约束姿态偏离。必要时允许经过限制的肩部自由度。只重复现有阶段不足以解决问题。
4. 加接触进入/退出滞回和时间连续性项，修正结果仍需复检。不要在求解后无约束平滑，因为这可能重新穿入。

回归至少同时检查最终碰撞残差、接触表面间距、手臂姿态偏离和相邻帧跳变；继续做 C4D 导入后骨骼位置对照。不能只以 solver success、单个全局 maxResidual 或截图外观验收。上述改进尚未实现；本轮完成的是实测审计和反例验证。

## 复现

使用 UTF-8 manifest，前三行分别为来源 PMX、目标 PMX、动作 VMD 的绝对路径；保持原资产不变。将对应 libMMD 提交归档到独立目录，配置本目录的 CMake：

```powershell
cmake -S docs/validation/vmd-sizing/algorithm-audit-20261010 -B S:/tmp/sizing-audit-repro -G "Visual Studio 18 2026" -A x64 -DCORE_ROOT=S:/tmp/cmt-sizing-audit-20261010/baseline
cmake --build S:/tmp/sizing-audit-repro --config Release --target sizing_audit
S:/tmp/sizing-audit-repro/Release/sizing_audit.exe S:/tmp/cmt-sizing-migration-assets.txt S:/tmp/sizing-audit-results/baseline-results
```

另外建立带实验补丁的源码副本，配置新的 build 目录并生成 `cleanup-results`，然后运行 `python -X utf8 summarize.py S:/tmp/sizing-audit-results`。这是使用私有 FK 接口的审计工具，需与记录的 libMMD 版本一起使用。后续进度回调改动不属于此次算法基线。
