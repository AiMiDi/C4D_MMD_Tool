# 动作适配状态栏进度验证

2026-10-10：动作适配增加 C4D 状态栏进度，核心只提供 SDK 无关的观察回调，不改变求解目标、数值运算或默认参数。

## 行为

- `Run` / `RunBatch` 接受可选 `ProgressCallback`，上报阶段、已完成/总工作量以及角色序号。扭转、回避、接触、多人接触按帧，相机按关键帧；没有可分工作量时使用忙碌指示。
- 百分比是当前阶段进度，不是整个任务的时间估算，阶段切换会重新计数。
- `HostSession` 将回调合并为最多约每 100 ms 一次的异步主线程任务，调用 `StatusSetText` / `StatusSetBar` / `StatusSetSpin`。不从工作线程调用 UI；队列只持有进度状态的弱引用。
- UI 和 MCP 启动走相同通道。面板关闭或客户端停止轮询不影响主线程进度更新。任务终止、异常、取消、释放会收尾；同一插件的旧任务不会清掉新任务的状态栏。
- 读取来源、模型快照、预览、应用、导出以作用域管理忙碌指示，提前返回也会清除。第三方 MCP 视口捕获不在此范围。
- MCP 任务返回增加可选 `progress`，旧宿主没有该字段时仍可使用当前客户端。中文资源沿用 `\u` 编码，同时更新英文和两个 SDK 资源布局。

## 未通过与边界

- 同一真实模型在预览后执行 Apply，被 `目标绑定模型已改变` 校验拒绝。记录在 `progress-native-receipt.json`；尚未确定原因及改动归属，不算 Apply 成功验证。
- 释放正在显示的预览时，第三方 host Python 的后处理访问了已关闭的文档，导致外层结果不确定。随后通过原操作 ID 查询确认释放已成功，没有重放释放操作。
- R20 完整构建被工作区已有、未提交的 PE 同步代码中的三处 const 兼容问题阻断：`pmx_mesh_provenance.hpp:48/50` 和 `mmd_mesh_manager.cpp:2012`。没有修改这些其他工作的文件，也没有声称 R20 出包通过。
- 当前是本地实现与验证，没有为这次进度功能新发 Release。

`receipt.json` 记录二进制身份与验证边界。完整 native 操作和构建日志在 `output/motion-sizing-audit-20261010/`。算法缺口及改进建议见相邻 `algorithm-audit-20261010/README.md`。
