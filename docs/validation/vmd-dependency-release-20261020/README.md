# Windows Release 依赖优化验证

本轮修复 SDK 构建中的 Bullet / libMMD Release 编译选项。保留单线程世界、默认每动画帧 3 个物理子步以及原有求解器设置。

## 原因与实现

Maxon SDK 的 `MaxonCompilerHelper_SetConfigurations` 会清空全局、各配置的 C++ flags。插件目标另有 SDK 编译选项，但依赖没有获得同样的优化设置。不能仅凭 CMake cache 中出现 `/O2` 判断最终编译已启用优化。

本轮原始依赖来自 `_build_msvc/sdk_2027_v143/bin/Release/libs`。7 个 `.lib` 的 SHA-256 均与隔离宿主使用的依赖相同；对应 214 条实际编译命令没有 `/O*` 优化选项。此前 SDK 2026 的记录提供了排查线索，本次受控对比使用的是 SDK 2027 的实际原始依赖。

`cmake/mmdtool_plugin_dependencies.cmake` 在 Windows MSVC SDK 构建中，对 LinearMath、Bullet3Common、BulletInverseDynamics、BulletCollision、BulletDynamics、BulletSoftBody、libMMD 的 Release 目标设置：

```text
/O2 /fp:strict /Ob0 /Oi-
```

这些设置启用普通代码优化，同时约束浮点表达式、内联和内建函数替换。Debug 选项保持原样；独立依赖构建保留其工具链默认值；预编译依赖路径仍直接使用调用方提供的库。

实际编译命令审计确认，214 条命令只改变上述指定选项（比较时忽略输出 PDB 路径）。7 个目标的生成项目也验证了 Release 设置和 Debug 不变。

## 被排除的方案

先测试全量 `/O2`，再测试 `/O2 /fp:precise`。两者虽然有提速，但物理开启时的骨骼和变形网格与基线不同，不能作为本轮保持效果的优化保留。物理关闭时均与基线一致。

`/O2 /fp:precise` 的完整 620 帧回放中，12 个网格检查点的平均欧氏误差为 0.01830，P95 为 0.07922，最大为 4.09392（第 479 帧）。平均误差小不代表局部摆动一致，因此最终采用更保守的组合。

## 当前场景结果

场景仍为阿芙 2.0 的原始快照：30 fps，625 根骨骼、479 个刚体、748 个约束、35 个网格和 70,222 个顶点。子步数保持 3，即 90 Hz；不改变动作时长。

已经通过的效果检查：

- 连续播放、跳帧、混合物理前后阶段、全部物理后阶段、关闭物理共 112 个记录，全部骨骼 Mg/Ml 和实际变形网格逐字节一致。
- 从第 0 帧连续计算到第 619 帧，每帧全部骨骼位置一致；12 个检查点的完整骨骼矩阵和全部变形顶点一致，共 25 个二进制文件。
- 第 619 帧的原生视口截图与基线逐字节一致。
- 子步数默认值、范围、旧文件迁移、撤销、克隆、保存重开，以及同帧修改参数/原始容器/工程 fps 后的冷重置检查通过。

性能采用 profiling 关闭的 Release 版本。每次加载同一快照，预热第 0、540–559 帧，测量第 560–619 帧的 `ExecutePasses`。同时记录 wall time 和调用线程 CPU 时间；包含 Skin/缓存求值，排除视口绘制和数据导出。编译和依赖测试不与性能采样并行。

关闭插桩的四次连续播放采样，每次 60 帧：

| 版本 | 各次平均 wall time（ms/帧） | 合并平均 |
| --- | --- | --- |
| 原版 | 52.62、53.80、51.81、53.77 | 53.00 |
| 优化版 | 42.06、44.82、43.04、43.90 | 43.45 |

整帧计算平均减少约 18.0%。后两次原版采样在候选测试后重新换回原版完成，避免仅依赖一次前后对比。最终版和最初保守候选使用相同的依赖编译选项。

以下为开启插桩后各 120 个帧记录的 inclusive 阶段耗时，不能与上表的 OFF wall time 直接相减，嵌套阶段也不能相加：

| 阶段 | 原版（ms/帧） | 优化版（ms/帧） |
| --- | --- | --- |
| Bullet 总计 | 23.06 | 13.77 |
| 碰撞检测 | 12.26 | 6.88 |
| AABB 更新 | 6.92 | 3.20 |
| 碰撞分派 | 5.19 | 3.57 |
| 约束求解 | 9.62 | 6.12 |

Bullet 总耗时减少约 40.3%。每个版本的 120 帧都记录到 360 个 Bullet 子步，没有通过少算子步获得收益。

关闭物理对照仍为约 27–31 ms/帧，本轮未确认该路径提速。基线两次为 26.47、28.10 ms，优化版四次为 28.17、30.71、27.08、30.92 ms；全部保留，不将其描述为改善。其波动与测量范围意味着整条 C4D 求值链还需要单独优化。完整数组见 `receipt.json`。

计时不能直接等同于视口播放 FPS；未达到 16.67 ms 的 60 fps 帧预算。
