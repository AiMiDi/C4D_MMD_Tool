# VMD 播放：Bullet 分阶段分析、控制器复用与多线程试验

本轮完成 Bullet 内部 18 个阶段的可关闭插桩，并把控制器骨链分类收紧到一次模型求值内复用。正式候选保持原有 Bullet 世界、依赖库和物理参数。隔离试验中的多线程世界未复现崩溃，但改变了当前场景的物理输出，因此没有合入正式运行路径。

## 测量方法与边界

- Cinema 4D 2027，使用同一场景快照：30 FPS、625 骨骼、479 刚体、748 约束、35 个蒙皮对象、70,222 顶点。原场景保持不变，宿主操作仅通过 MCP。
- 每次加载新快照，预热帧 0 和 540–559，测量帧 560–619。计时只包含 `ExecutePasses(None, True, True, True, BUILDFLAGS_NONE)`，包含蒙皮/缓存求值，不包含视口绘制。效果采样与性能采样分开。
- 细分数据使用宏 ON 的两个完整连续播放批次，共 120 个时间桶。只保留包含 `model.execute` 的帧记录，排除参数回调形成的额外记录。正式包耗时使用宏 OFF。
- 后台存在其他任务的 MSBuild/cl，未终止这些进程。整帧 wall/CPU 时间均有明显漂移，不能据此给出稳定提升百分比或实际播放 FPS。线程 CPU 为 Windows 聚合计数，按 60 帧取均值。
- 可复核数据见 [receipt.json](receipt.json)。完整快照、二进制、原始数组及日志保留在 `S:/tmp/cmt_vmd_profile_20261019/optimization_round4` 及同级各采样目录。

## 已采用的控制器改动

`MMDModelManagerObject::Execute` 内建立 `mmd_control_workflow::EvaluationContext`，由初始校验、活动控制器检测、各层求解和最终校验共享。只复用骨链成员和名称分类；控制器链接、模式、层级和矩阵仍在使用时读取。不跨模型求值、不按帧号缓存，因此同一帧修改参数后仍会重新扫描。没有上下文的 UI 调用保持原行为。

当前场景骨链扫描从每次求值 **6 次降到 1 次**。新版本 `control.chains` 为开启物理约 **0.599 ms/帧**、关闭物理约 **0.689 ms/帧**；上一轮对应约 3.876/3.594 ms，两个轮次受环境和插桩边界影响，不将其换算成整帧提升。

## 多线程世界试验

试验代码只存在隔离目录，保留差异于 [experimental-mt.patch](experimental-mt.patch)。它没有进入正式 `dependency/libMMD` 或最终插件：

- Bullet、libMMD、插件统一使用 `BT_THREADSAFE=1` 重建，避免类布局或线程配置不一致。
- 在插件启动阶段创建默认任务调度器，退出时恢复原调度器；求解器池的生命周期长于世界。
- 使用 `btDiscreteDynamicsWorldMt` 加独立岛求解器池，每个岛仍使用顺序求解器，没有启用大岛内部 MT 求解器。
- 同一个试验二进制分别运行串行世界、MT 世界 1 线程、MT 世界 4 线程，每种均执行 112 组效果采样和 60 帧 CPU 计时，包含加载、跳帧、重置和正常退出。

本轮三个配置均未崩溃。这不能解释或证明修复了之前遇到的崩溃；调度器初始化、ABI 一致性和生命周期只是本次明确控制的条件。

| 对比 | 112 组输出是否全部精确一致 | 结论 |
|---|---|---|
| 正式版 vs 重建依赖后的试验串行世界 | 否 | 依赖重建已有输出差异 |
| 同一试验包的串行世界 vs MT 1 线程 | 否 | 更换世界实现也改变物理输出 |
| MT 1 线程 vs MT 4 线程 | **是** | 本场景线程数变化未引入额外差异 |
| 正式版 vs MT 4 线程 | 否 | 不满足保持物理效果不变的要求 |

所有这些比较的关闭物理场景均精确一致。正式版与 MT 4 线程的连续播放中，蒙皮顶点坐标最大分量差约 1.758；全 after-deform 测试约 6.046，属于场景坐标单位，不是百分比。详细分场景误差见 receipt。

拓扑采样在各世界第 20 次更新进行：452 个动态刚体、748 个约束，只有 4–5 个动态岛，最大岛包含 299 或 440 个动态刚体。这是预热位置的采样，不是全播放区间的统计范围。大部分刚体集中在一个岛，独立岛并行能力有限；此试验的碰撞检测仍串行。

同一试验包单次 60 帧测量：串行世界 wall/调用线程 CPU 为 42.863/42.448 ms，MT 1 线程为 42.560/41.927 ms，MT 4 线程为 62.365/61.458 ms。后台负载与线程调度不同，不能把这组差值定性为算法固定加速或固定减速；没有得到采用 MT 世界的性能依据。

另一个必须隔离的因素是依赖编译配置：[dependency-build-flags.json](dependency-build-flags.json) 保存了实际编译命令。原依赖 Release 命令没有 `/O2`，试验重建依赖有 `/O2 /Ob2`，且 `NDEBUG`、异常及线程宏等配置不同。因此正式版和试验串行世界的计时差不能归因于多线程。重建后的输出差异也尚未进一步归因；本轮没有更改正式依赖编译选项。

## 后续并行点选择

根据当前测量，优先研究碰撞检测侧，不把整个 MT 世界作为默认替换：

1. 先将 `updateAabbs` 细分为形状/变换的包围盒计算与 `setAabb`/动态树提交，判定 8.086 ms 的具体组成。
2. 若纯计算占比足够，再尝试基于纯数据的逐刚体并行计算，仍按原顺序串行提交 broadphase；不得直接并行修改共享动态树。重新验证精确输出与线程调度成本。
3. 大岛内的关节准备约 4.108 ms 也值得后续调查，但涉及共享求解器状态，优先级低于上述计算/提交分离。当前积分和运动预测不足 1 ms，不优先投入。
4. 依赖编译优化应单独建立同选项、串行世界的对照。它与并行实验分开验收，避免混淆收益或物理漂移。

这是依据结果选择的下一步范围；本轮尚未把 AABB 或求解器改成并行。
