## 插桩开销边界

三种状态均做了三轮独立加载、20 帧预热、60 帧计时，采集与文件保存不计入外部计时区间；
每次 ExecutePasses 中触发的阶段日志输出仍属于该次外部计时的成本。

| 模式 | 外部 ExecutePasses 平均耗时 |
| --- | ---: |
| 宏关闭，环境变量为启用 | 327.82 ms |
| 宏开启，运行时关闭 | 212.06 ms |
| 宏开启，记录阶段日志 | 130.09 ms |

测试期间观察到并行 Unreal 原生编译，宿主明显受到系统负载波动影响；这些结果没有可靠的顺序关系，
**不能用它们计算插桩开销百分比，也不能据此声称插桩加速了播放**。宏关闭三轮中的一轮均值达到 622.05 ms，
进一步说明当前环境不适合做小幅开销验收。慢的一次三轮 MCP 请求超出 55 秒后继续执行，后续三个结果文件均完成；没有重复排入请求。

显式核心微基准的一次记录：每对嵌套 scope，宏关闭约 0.31–0.36 ns（仅剩基准负载），
宏开启但未启用统计约 5.54 ns，启用统计约 117.46 ns。
该微基准不包括 SDK 入口、根统计合并、JSON 格式化与 I/O，不能代替原生端到端开销验收。

## 出包保护

- Release/package presets、生产 CI 构建显式关闭宏；`cmt-package` 覆盖旧 SDK cache。
- 实际配置根构建为 `ON`，生成的 `cmt-package.vcxproj` 仍为全部 9 个 SDK 传 `OFF`（四种配置共 36 条命令），无传 `ON` 的命令。
- 真实启用模块包含保留标记，被 CMake 出包检查拒绝；真实关闭模块不含标记并通过。
- Windows Inno 与 macOS ZIP 包装前均检查实际模块；缓存审计同时要求明确 OFF。
- 测试还覆盖 `.xdl64`、`.xlib`、`.dylib`、嵌套目录和缺少模块时拒绝。macOS 此处为保护脚本 fixture，未进行原生构建。
