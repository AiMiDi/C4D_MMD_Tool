# 每动画帧物理子步数：配置与原生验证

2026-10-20。模型“物理”页新增“每动画帧物理子步数”，默认 3，范围 1–10。
默认值在当前 30 fps 场景中等价于上一版固定 90 Hz；本次默认设置的物理结果没有变化。

## 配置语义

- Bullet 固定频率 = 文档 fps × 子步数；动画每帧仍推进 `1 / 文档 fps` 秒。
- 30 fps 下，2 / 3 / 4 步对应 60 / 90 / 120 Hz。60 fps 下，默认 3 步对应 180 Hz。
- 修改子步数或文档 fps 会冷重置物理，即使时间没有变化、关闭了“跳帧时重置”，或脚本直接修改容器。
- 同帧修改会清除已经发布的物理骨骼姿态缓存，防止冷重建后继续显示旧姿态。
- 参数不支持动画；旧场景缺少字段时使用 3，非法输入限制到 1–10。
- 参数 ID 显式追加为 `MODEL_PHYSICS_SUBSTEPS = 3200`，原有序列化 ID 不变。
- 两套资源 `S24_up` / `R20-S24` 及中英文标签均已更新。

降低子步数会改变物理轨迹。此前的质量比较仍适用于当前 30 fps 场景：
见 [120 / 90 / 60 Hz 对比](../vmd-physics-90hz-20261020/README.md)。
默认 3 步维持上一轮选择的效果和速度折中，不代表重新恢复到 120 Hz 的轨迹。

## 进一步优化方向

1. **先独立验证 Release 编译优化。** 审计现有 SDK 2026 Release 的实际
   `CL.command.1.tlog`：BulletDynamics 42 条、BulletCollision 97 条、libMMD 34 条
   C++ 编译命令均没有 `/O*` 优化选项。SDK 的 `MaxonCompilerHelper_SetConfigurations`
   会清空 `CMAKE_CXX_FLAGS` 及各配置选项，插件自身另有目标级设置，依赖目标不能依赖缓存里显示的
   `/O2` 就认为生效。下一轮应仅给普通单线程依赖补足 Release 优化，再对比耗时、几何和稳定性。
   本次没有修改依赖编译参数，收益尚未测量；审计日志属于已有 SDK 2026 构建记录。
2. **拆分 AABB 计算与 broadphase 更新。** 上一轮 90 Hz 插桩中 AABB 阶段约 6.94 ms。
   当前 `updateSingleAabb` 同时计算包围盒并修改共享 broadphase；可先批量计算纯数据，
   再按原顺序提交更新。这是候选并行点，需要单独验证，不能直接把整个循环并行化。
3. **继续缩小碰撞派发和求解器热点。** 上一轮派发约 5.21 ms、求解约 9.51 ms。
   先确认编译优化后的分布，再选择缓存或并行工作。上述均为包含子阶段的计时，不能相加。

此前多线程 world 实验改变过轨迹，本次没有把它启用为默认路径；
也没有把当时混合了编译选项变化的速度差归因于多线程。
