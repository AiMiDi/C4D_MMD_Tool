# VMD 播放：移除纯姿态路径的重复权重通知

本轮在当前阿芙场景副本上，关闭插桩的 Release 完整求值耗时：带物理平均 **121.66 → 74.91 ms/帧（减少 38.4%）**；关闭物理 **84.83 → 48.84 ms/帧（减少 42.4%）**。两轮交替 A/B 均改善，骨骼和实际蒙皮顶点保持精确一致。

这些数字是 `ExecutePasses` 的完整求值时间，包含缓存生成，不包含视口绘制，不能当作实际播放 FPS。没有达到 60 FPS 验收。

## 原因与修改

旧实现每帧在物理写回和骨骼管理器覆写后，分别给所有网格、权重标签、Skin 发送脏标记和 `MSG_UPDATE`。当前场景有 35 个权重标签，每个都关联 625 根骨骼。独立通知探针测得，35 个权重标签仅 `MSG_UPDATE` 的中位耗时为 34.81 ms；仅设置脏标记约 0.037 ms。该探针用于定位，不代表整帧收益。

- `source/module/tools/object/mmd_model_runtime.cpp`：纯物理姿态写回调用 `MarkMeshHierarchyDirty(..., false)`；绑定状态提交和恢复仍走默认完整更新。
- `source/module/tools/object/mmd_bone_manager.cpp`：纯姿态覆写保留网格和 Skin 通知，取消所有权重标签的重复通知。
- `source/utils/cmt_runtime_profile.hpp`：增加 `mesh.invalidate`、`mesh.weight_update` 阶段，便于复查网格通知与真实权重更新。

Bullet 步长、子步、求解器、物理重置、刚体与约束，以及矩阵写回算法均未修改。真实权重编辑仍使用原生 `WeightDirty()` / 更新通知；编辑模式切换仍刷新绑定数据。

## 环境与计时方法

- Cinema 4D 2027.0.0，MSVC v143、Release；原场景保存快照，625 骨骼、479 刚体、748 约束、35 网格、70,222 顶点，30 FPS。
- 原生操作仅经 MCP，使用任务独立配置目录和端口 5557。测试均加载新副本，保留原文档状态；未操作用户工作文档。
- 冻结源文件和依赖，基线/候选源代码仅上述三个文件不同。矩阵确定性修复在两边均已存在。
- 最终性能使用宏关闭的旧/新 Release，顺序 A1 → B1 → A2 → B2。每次从快照加载，先求值帧 0，再预热 540–559，计时 560–619 共 60 帧；每种状态累计 120 帧。
- 计时不包含采样、文件写入和视口绘制。性能轮关闭几何采集，效果采集单独运行。
- 环境仍有其他 MSBuild 进程，数字存在漂移；报告全部轮次，结合阶段耗时确认改善，不能泛化为所有模型的固定收益。
