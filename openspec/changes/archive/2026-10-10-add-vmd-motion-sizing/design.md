# Design

## 生产 MCP 动作适配接口

复用现有生产 dispatcher、文档/对象句柄和 operation ID 去重；HostSession 分配独立会话任务句柄，保持 MCP 任务身份独立于 UI 编辑和测试桥。启动接受 1–16 个同文档角色，动作文件或稳定身份槽二选一，共享求解参数允许角色覆盖。新增 11 个工具：启动、状态、结果、取消、预览、关闭预览、应用、导出、相机应用、相机导出、释放。状态轮询不等待后台线程，结果提供分页诊断和阶段统计；应用复验整个批次的目标绑定，导出使用既有暂存提交及文件身份验证。

最多保留 4 个任务，900 秒无访问或文档关闭后在后续适配调用清理；运行中任务先请求取消，终态后销毁，避免主线程析构 future 时等待。计算状态为独立 job_state，外层 MCP envelope 记录单次启动或查询操作。完整字段及默认值见 docs/dev/motion-sizing-mcp.md。普通 Release 编译和协议/核心测试证据独立于新模块的原生业务验证；运行中的旧模块不得充当新接口验收。

## Context

现有 libMMD 已提供 Eigen、PMX/VMD 读写和骨骼插值；CMTSceneManager 支持事务式内存 VMD 导入。vmd_sizing e5c3035 的 MoveService 同时包含非均匀缩放、中心偏移和 IK 横向偏移；部分偏移依赖网格脚尖参考点。主窗口资源和所有 SDK 共用 source。

## Goals / Non-Goals

目标：单角色文件 VMD 输入，来源 PMX、目标当前 MMD 模型绑定快照；原始、比例、偏移三阶段不可变结果；完整 C4D 预览、提交和保存重开闭环。
初始 P0/P1 只包括上述范围；本轮按用户要求扩展 P2 姿态与扭转、P3 避让与接触、P4 多人/相机。骨骼或参考点不足时明确报告，不伪造成功。

## P2–P4 扩展设计

- 姿态阶段保留上游手臂 `from.inverse * motion * to` 轴补偿公式；肩、躯干通过对应绑定骨段方向进行轴补偿。扭转采用 swing/twist 分解并保持串联旋转乘积。与上游迭代肘角搜索、特定模型虚拟骨骼和滤波策略有差异，不把它们宣称为全量逐帧移植。
- 约束阶段在整数 VMD 帧离线求解。只烘焙参与校正的轨道，保留其他通道；新增关键帧使用线性曲线。有限帧数/迭代数/输出键数预算防止畸形输入分配失控。
- 高级 FK 复用 libMMD 播放插值，使用绑定平移、父级累计变换和独立付与依赖图。支持旋转/平移、局部/多重付与及负权重；循环辅助分支隔离并报告。固定轴仅约束求解新增旋转，不改写输入播放姿态。外部父级仍不支持。
- 球、盒、胶囊在绑定骨骼变换后的局部空间计算有符号距离，有限 CCD 修正手肘和手腕。仅运动学避让，不模拟布料或动态刚体。报告采样点的残余穿透；不声称完整网格无穿插。
- 根据原动作识别左右手腕/指尖靠近与地面接触，将约束映射到目标模型；跨角色接触使用所有角色同一帧的源/目标位置。记录目标、最终误差和未收敛数量。
- 多人使用一个不可变输入批次、统一取消令牌和完整成功边界。UI 队列中的每个角色拥有独立来源 PMX/VMD、目标链接；角色 VMD 原点为公共 MMD 空间。目标场景对象的额外变换不参与文件坐标求解。
- 相机根据共同骨骼在相机平面的范围调整取景中心和距离，保留角度、旋转、投影模式及曲线。独立相机 VMD 输入/输出，保留原始/调整结果。与原相机算法的可见点选择和近景特例不同，证据单独标记。
- 阶段扩展为原始、比例、偏移、姿态、扭转、避让、接触、多人。禁用阶段复制上一阶段。主线程快照、后台运算、过期校验和独立预览继续沿用 P1 边界。

## Decisions

- 独立 C++17 核心保留在本仓库，使用 libMMD 数据类型与 Eigen double 中间计算，写回 float；生产代码不依赖 Python。相比直接移植 UI/对象字典，连续存储和预解析名称更便于测试维护。
- P0 使用上游源码的隔离副本构建 Cython，保存 revision、输入/源码 SHA256、命令、输出及依赖版本。固定可再生合成模型/动作，另记录实际模型验证范围；合成基准不宣称完整 MMD 品质。
- 保留上游 MoveService 单角色公式（包括中心 Y 使用目标脚踝的历史行为），修复/优化另行记录。对退化分母、非有限值、循环层级及无动作明确返回诊断。
- 阶段顺序为原始、比例缩放、局部偏移。偏移按目标骨骼累计旋转转换为动作位移；保持原曲线字节、旋转、morph、IK/visibility 和相机数据。P1 不插帧。
- sizing 内部旋转采样单独保留上游 VmdData 的到达帧曲线、第 4 组旋转曲线副本和 15 次二分求值；现有 libMMD 播放器使用不同的分段约定，不能直接复用。错帧关键帧基准覆盖此差异。

上述上游采样仅保留于 P1 位移基准兼容路径。P2–P4 离线姿态必须与实际 C4D 播放一致，直接复用 `InterpolateBoneKeys` 的通道布局和起点曲线约定；真实素材的 90 个位置样本验证此边界。非共线扭转通过父骨方向和子骨旋转补偿保持末端姿态，只有几何上不可消除的半径误差才限制转移量。共享手臂的接触目标采用 Eigen 阻尼最小二乘、角步限制和回溯，连接接触组共享目标，避免逐个 CCD 互相覆盖。仍报告不可达和预算内未收敛的残差。
- 主线程复制绑定模型与输入；后台只计算独立数据，取消令牌不碰 SDK。主线程轮询完成结果，显示阶段；应用前重新验证目标输入快照。
- 预览使用工具拥有的独立 C4D 文档，以同目标模型两份实例对比。阶段切换只替换预览动作；原文档保持不变。视口播放由 C4D 时间轴驱动。
- 新槽提交复用 LoadVMDMotion Undo 边界。模型位置倍率在适配器边界处理，核心统一为 PMX/VMD 单位。绑定快照在隔离副本读取，避免模式切换提交艺术家当前姿态。
- 入口使用现有注册命令的顶层动态条目，在扩展菜单平级显示工具面板与 VMD 动作适配。原工具面板顶部不增加按钮；两个窗口独立恢复布局，原命令快捷键保持工具面板行为。

## Risks / Trade-offs

- 原 Cython 环境过旧 → 记录构建兼容性修补，不修改算法来源仓库。
- 上游名称与虚拟骨架存在隐含约定 → 预检标准日文骨骼和网格参考点，报告缺失，不静默近似。
- 物理与控制器污染对比 → 独立预览重建输入，关闭物理；后续质量验收另做。
- 用户关闭文档或修改模型 → 使用链接和绑定快照再校验，拒绝过期提交。
- 数据大导致内存增长 → 当前每角色保存八个动作阶段和两个预览模型，无全迭代记录。

## Migration Plan

新增工具入口，不改变现有导入或磁盘格式。移除新增工具即可回退；应用生成的槽仍使用已有持久化格式。

## 场景输入与实时交互

面板顶部复用原工具 Logo，按原始 300:95 比例在真实控件区域居中绘制，独立于局部重绘矩形和窗口大小。模型链接框支持拖入场景 MMD 管理器，动画下拉框以稳定 runtime identity 选择槽，快照仅在隔离文档副本中切换和导出所选槽。

自动预览默认开启；参数编辑采用 350 ms debounce 与取消令牌，后台任务结束后仅发布最新输入结果。使用独立模型前后比较，不覆盖来源动画；保留预览帧。关闭预览时关闭自动重新打开。输入和预览构造仍在主线程，不承诺大型角色的无延迟交互。

## MCP 面板同步

MCP dispatcher 保留任务所有权并发布主线程面板快照：稳定模型链接、来源/动作、每角色的完整求解参数、相机、角色与阶段/叠加状态。面板通过修订号同步最新显式操作；状态轮询不覆盖正在编辑的草稿。稍后打开面板也能读取快照，并通过弱引用使用同一结果和预览。UI 修改输入会脱离外部会话并启动独立任务，保留没有 UI 控件的高级参数及其他角色的配置；关闭面板不取消 MCP 任务。释放/过期撤回已发布状态且对话框不能延长任务寿命。

## libMMD 下沉与队列一致性（2026-10-10）

用户要求在修复和再次复核后将可复用计算移入现有 libMMD。公共入口为 `libMMD/Model/MMD/MMDMotionSizing.h`，命名空间 `libmmd::sizing`；五职责目录位于 `src/MotionSizing`，文件采用 `MMDMotion*` 命名。计算代码、核心测试、合成样例和上游 MIT 许可由 libMMD 拥有，主库 target 直接编译；删除旧独立 target 与兼容 include。公共头随库安装，私有 Pose/Solvers 头仅内部测试使用。C4D 快照、异步会话、MCP 和 UI 保留在插件侧。

MSVC 下七个计算源文件显式保留原 SSE2 编译配置，避免直接继承 libMMD AVX2 后改变迭代接触解。使用私有 Pose 类型的测试和探针同样使用 SSE2；仅标量数组跨边界的 PMXNode 付与参考 TU 跟随 libMMD 播放部分的 AVX2 开关。独立非 AVX2 构建另做验证；最终真实资产八阶段及相机共九份 VMD 与迁移前逐字节一致。插件测试从实际 libMMD target 的 SOURCE_DIR 获取根目录，以支持 CMT_LIBMMD_SOURCE_DIR 覆盖。

角色队列增加显式新角色草稿：选择新目标不覆盖旧角色，入队前不自动求解；选择已有目标加载自身配置。移除角色后加载相邻有效角色，最后一个移除后清空目标/路径并停止自动请求。MCP 发布的隐藏求解参数和角色独立配置继续保留。
