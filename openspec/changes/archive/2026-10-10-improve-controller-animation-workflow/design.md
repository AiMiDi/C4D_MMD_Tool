# Design

## Context

见 proposal.md。控制器相对变换当前作为动画增量进入 MMD 求值，PMX IK 是腿部的原始解算来源。共享工作区有独立修改，本次在工作树中以已提交版本为基线开发。

## Goals / Non-Goals

目标是按任务整理控制层，并在 FK/IK 间保持当前姿势。实现以 C4D/MMD 的既有动画、绑定和物理接口为基础，不直接依赖 Blender 或引入 Rigify 数据结构。

## Decisions

- 显示、选中、穿透绘制和悬停共享同一部位/用途过滤；隐藏不改变输入贡献。
- 用 Auto/FK/IK 离散控制权保留旧场景的 Auto 行为。FK 在零旋转时仍持有链；IK 忽略同链 FK 输入。预设调用同一匹配路径。
- 手脚显式 IK 在对应层的动画/附加变换之后，使用实际两段长度解算，经过既有运行时覆盖路径发布。不可达目标按肢长限制；Auto 和脚尖沿用 PMX IK。
- 模式变更在当前时刻匹配公开输入和扭转，不修改模型绑定。已有轨道在当前时刻登记匹配键，保留其他键；没有轨道时只更新输入。反向匹配使用实际求值姿势。
- 复用纯名称分类，支持完整标准手指名，避免装饰/变形副骨误识别。
- 显示预设和关键帧/重置是显式操作；打键统一写 C4D 控制器轨道，不要求 MMD 槽；只处理本模型当前可见且选中的管理控制器，事务支持撤销。

## Risks / Trade-offs

- 不标准、缺失、零长度、固定轴或跨后物理阶段的链 → 不创建不成立的手部 IK，保留原有 Auto 控制。
- PMX 附加变换及物理可能影响匹配 → 在 PMX/VMD 场景验证姿势、重复求值、撤销和保存重开。
- 控制器拥挤 → 部位独显、用途分组、关闭辅助选择，并使用不同轮廓和比例。
