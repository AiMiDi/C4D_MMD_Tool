# 实施设计

## Context

动机和范围见 proposal.md。维护源码为 source/，各 SDK 薄包装共享 CMake 与资源。当前动作骨骼数据以 slot 保存在 tag，表情和 IK 使用 CTrack；ModelManager 数据磁盘版本为 4。C4D 尚在用户安装过程中，原生运行验收不能与编译测试混用。

## Goals / Non-Goals

目标是完成现有用户界面承诺的行为并建立可运行的验证入口；通过渐进职责拆分和执行计划缓存降低维护成本。依赖提交、SDK 注册 ID 和现有版本 4 数据布局不变；不安装或升级 C4D。

## Decisions

1. 动画槽保存骨骼、表情及模型信息真值；切槽前捕获旧轨道，再重建新槽轨道。数据版本 5 在旧布局后追加信息，老文件将现有活动 IK 轨道迁移到当前槽。
2. 动作烘焙复制文档并建立链接重映射，在副本中以 30fps 顺序求值，包括最终 IK/物理。源场景无需回滚副作用。
3. 骨骼执行计划由 BoneManager 缓存，包含实际存在的层、排序和分层 pre/post IK 索引。既有层级/append 脏通知触发重建；运行态参数快照防止脚本直接写参造成缓存漂移。逐层同步仍保留 append/IK 的交错顺序。
4. ModelManager 的纯转换、材质计算和协调实现分文件维护，C4D ObjectData 入口保持稳定。
5. 构建目录 res 是真实副本；SDK source/res 输入可继续使用链接。资源同步处理链接本身并验证目标边界，发布默认重置配置，开发保留配置采用显式选项。
6. PR/main 轻量编译最新 SDK 并执行功能 CTest；完整矩阵用于发布，benchmark 独立运行。根与内层 SDK 配置同名显式传递。
7. C4D Python 回归需要明确编译开关启用的测试桥接，普通发布默认关闭。通过确定性 PMX/VMD 输入和 JSON 回执证明运行结果。
8. 相机使用原生垂直 FOV 弧度；生成子相机的旧 APERTURE 轨道按隐藏 schema 0 → 1 一次性迁移，保留插值和时间切线。普通相机传感器参数保持独立。
9. 场景动作入口先捕获模型子树 Undo，返回失败或 C++ 异常时只撤销本次分组并恢复时间范围；预检与合并数组先于写入。配置文件旧版混用的旋转枚举/烘焙布尔类型规范化后保留旧选择。

## Risks / Trade-offs

- 场景迁移出错 → 仅追加版本 5 数据并测试旧版本读取边界。
- 缓存遗漏直接参数写入 → 在计划入口比较参与排序/分组的参数快照，只有变化时排序。
- 原生 host 不可用 → 本轮完成脚本及非原生检查，运行验收保持待执行。
- SDK 版本跨度 → 复用 cmt_marco.h 兼容设施，至少编译 2026 与旧 SDK 边界版本。
- 临时输出删除误伤 → 同步脚本拒绝源/目标重叠，移除 reparse point 本身后才替换真实输出目录。

## Migration Plan

完成源码和工具检查、依赖功能测试、最新 SDK 编译后，保留 reviewable diff。原生运行可用后执行相同构建回归；所有旧 change 的验收复核后才归档。
